# APMS v2 — Data Model

Postgres 16. Every tenant-owned table carries `org_id`. Every foreign key is a
real foreign key.

## Entity overview

```
Organization
   ├── Membership ──> User
   └── ParkingLot
          └── Camera
                 └── ParkingSlot
                        ├── SlotState      (1:1, current status, denormalised)
                        └── OccupancyEvent (1:N, append-only, source of truth)
```

Add a CHECK constraint that `polygon` has exactly 4 points. Malformed geometry

### SlotState
One row per slot. Denormalised current status so the live view is a single
indexed read instead of a window function over the event table.

| Field | Type | Notes |
|---|---|---|
| slot_id | FK → ParkingSlot, PK, CASCADE | one-to-one |
| org_id | FK → Organization, CASCADE | |
| status | enum: `VACANT`, `OCCUPIED`, `UNKNOWN` | |
| confidence | numeric(4,3) nullable | |
| since | timestamptz | when this status began — gives dwell time for free |
| updated_at | timestamptz | |

`UNKNOWN` is set by the server when a camera's heartbeat goes stale. v1 had no
way to express "we don't know", which meant a dead camera showed stale vacancy.

### OccupancyEvent
Append-only. This is the source of truth; `SlotState` is a cache of its tail.

| Field | Type | Notes |
|---|---|---|
| id | UUID PK | **generated by the worker**, enforces idempotency |
| org_id | FK → Organization, CASCADE | |
| slot_id | FK → ParkingSlot, CASCADE | |
| camera_id | FK → Camera, CASCADE | |
| previous_status | enum | |
| status | enum: `VACANT`, `OCCUPIED` | |
| confidence | numeric(4,3) | |
| observed_at | timestamptz | worker's clock, when the change occurred |
| received_at | timestamptz | server clock, on insert |
| model_version | varchar(64) | which model produced it — essential for comparing runs |

Never update or delete rows here. A retry with the same `id` is a no-op via
`ON CONFLICT DO NOTHING`.

## Indexes

```sql
CREATE INDEX ON occupancy_event (slot_id, observed_at DESC);
CREATE INDEX ON occupancy_event (org_id, observed_at DESC);
CREATE INDEX ON slot_state (org_id, status);
CREATE INDEX ON parking_slot (camera_id) WHERE is_active;
CREATE INDEX ON camera (org_id, last_seen_at);
```

The first one carries the analytics queries. Without it, dwell-time calculation
degrades badly once the event table passes a few hundred thousand rows.

## Derived metrics

All three come from `OccupancyEvent` with no extra tables:

- **Occupancy rate**: fraction of slots with `status = OCCUPIED`, sampled or
  time-weighted over a window
- **Dwell time**: for each `OCCUPIED` event, the interval until the next event
  for that slot
- **Turnover**: count of `VACANT → OCCUPIED` transitions per slot per day

## Org scoping

Implement a base manager that raises unless an org filter is applied, and a
mixin that resolves the org from the request. Do not rely on remembering to add
`.filter(org_id=...)` in each view — v1's unauthenticated ajax endpoint is
exactly what that failure looks like.

## What is deliberately absent

No `Subscription`, `Plan`, `Invoice`, `PaymentMethod`, `Notification`, or
`Device` table. No `SUPERADMIN` role. See `07_BACKLOG.md`. Absent, not stubbed.

## Implementation notes (Task 2.1)

- **Composite foreign keys** keep denormalised `org_id` consistent:
  camera→lot, slot→camera, slot_state→slot on `(parent_id, org_id)`, and on
  occupancy_event both `(camera_id, org_id) → camera` and
  `(slot_id, camera_id) → parking_slot`, so an event cannot claim a camera that
  does not own its slot. All NOT DEFERRABLE. Migration `parking/0002`.
- **occupancy_event is append-only by trigger.** UPDATE raises; DELETE is
  permitted only so deletes cascade.
- **Polygon**: the database enforces shape (four `[x, y]` pairs of non-negative
  numbers). The API enforces geometry — clockwise order, non-self-intersecting,
  inside the camera frame.
- **Slot label uniqueness is partial**, `(camera_id, label) WHERE is_active`,
  because slots are soft-deactivated. It also serves the active-slots-by-camera
  lookup, so the separate `(camera_id) WHERE is_active` index is omitted.
- **previous_status** allows UNKNOWN (first transition after a stale period);
  `status` does not. A CHECK requires `status <> previous_status`.
- **phone_number** is CHECKed against E.164 so one person cannot hold two
  accounts through formatting differences.
- **User** table is `app_user` (`user` is reserved). `is_staff` is removed: no
  admin consumes it and it would be a platform-wide third role.
- CHECKs added for confidence ∈ [0, 1], lat/lon ranges and pairing, frame
  dimensions > 0, and role and enum membership at the database.
- occupancy_event's single-column `org_id` and `slot_id` FK indexes are dropped
  as redundant with the two composite indexes.
- `received_at` is set by the application server on insert.

## Scoping manager semantics

`Model.objects` raises without an organization; `for_org(org)` is the only
entry. `Model.unscoped` is the explicit cross-tenant escape hatch. Reverse
relation managers and `full_clean()` raise by design; see
`server/tenancy/scoping.py`. The request-side mixin that resolves an
organization from a session arrives with auth in Task 2.3.
